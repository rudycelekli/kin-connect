# Environment setup

Copy `.env.example` to `.env` in a source checkout. `npm start` and `npm run dev` load it using Node.js 22.19+; variables already supplied by the process take precedence. The local `.env` is ignored by Git, excluded from Docker builds and excluded from release packages. Keep its permissions restricted. Do not paste credentials into chat, issues, logs, browser code, or the plugin ZIP.

For the hosted deployment, edit Railway's **Variables** for the existing Kin service. A local `.env` does not upload itself or configure Railway. Build-time `VITE_RELAY_URL` is public, so it may contain only a public relay URL. Never use `VITE_` for credentials.

| Variable                                                                         | Used today    | Purpose                                                                                                                                                                                        |
| -------------------------------------------------------------------------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PORT`                                                                           | Yes           | Listening port, default 4318.                                                                                                                                                                  |
| `KIN_DATA_DIR`                                                                   | Yes           | Private data directory; `.data` locally, `/data` on the existing persistent deployment.                                                                                                        |
| `KIN_PUBLIC_ORIGIN`                                                              | Yes           | Exact HTTPS canonical origin; leave unset for loopback-only local use. Hosted target: `https://www.kinconnections.com`.                                                                        |
| `KIN_PUBLIC_ALIASES`                                                             | Yes           | Comma-separated exact HTTPS origins whose Host and browser Origin are also allowed. Keep the old Railway origin during the transition. Requires public mode; private owner APIs stay disabled. |
| `KIN_ALLOWED_ORIGINS`                                                            | Yes           | Exact browser origins allowed to call relay and MCP, including a separate Pages client when needed. No wildcard.                                                                               |
| `VITE_RELAY_URL`                                                                 | Yes, at build | Public default relay address. No API keys here.                                                                                                                                                |
| `KIN_OPENAI_APPS_CHALLENGE`                                                      | Optional      | Exact verification token from the official submission portal. Leave unset until provided.                                                                                                      |
| `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`                                            | Reserved only | Empty server-only placeholders. No provider calls, model routing, intake upload, or automatic inference currently use them.                                                                    |
| `RESEND_API_KEY`, `RESEND_FROM_EMAIL`                                            | Reserved only | Future opt-in transactional email. No email is sent by current code. Resend does not provide a monitored support inbox.                                                                        |
| `KIN_OPERATOR_NAME`, `KIN_SUPPORT_EMAIL`, `KIN_PRIVACY_EMAIL`, `KIN_ABUSE_EMAIL` | Reserved only | Operator setup checklist. Runtime and public policies do not consume these yet; fill and verify actual contacts before publishing them.                                                        |

Kin's current agents use local deterministic policy checks and negotiation. They require no external model credentials. Connecting a ChatGPT MCP app does not require your OpenAI API key. Adding a provider later requires an implemented integration, explicit owner opt-in, a disclosure of exactly which data is sent, spending controls, and tests. Merely filling these placeholders enables none of those features.

Test a local setup with `npm start`, then open `http://127.0.0.1:4318`. For a hosted setup, run `npm run check:deployment -- --url https://www.kinconnections.com --output artifacts/domain-preflight.json`. See [deployment](deployment.md) for the persistent volume and origin transition, and [launch readiness](launch-readiness.md) for the separate host and operational gates.
